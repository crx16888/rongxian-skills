# 飞书写入与定点编辑（lark-cli）

## 1. 读文档

```bash
lark-cli --as bot docs +fetch --doc <doc_token> --doc-format markdown
```

- `--doc` 可传 token 或 URL；wiki 链接会自动解包
- 想看章节结构：`--scope outline --detail with-ids --doc-format xml`
- 想看某章的所有顶层块 id：`--scope range --start-block-id <h1 id> --end-block-id <下一章 h1 id> --detail with-ids --doc-format xml`

## 2. 整体覆盖（仅在文档是空白或用例新建时）

```bash
cd <工作目录>          # @file 必须是当前工作目录下的相对路径
lark-cli --as bot docs +update --doc <doc_token> --doc-format markdown --command overwrite --content @./plan.md
```

- **`@file` 只接受相对路径**，绝对路径会报 `unsafe file path`
- 文档首行写 `<title>活动全名</title>`，其后 `#` / `##` 分级且不跳级
- 支持 callout：`<callout emoji="🎯"><p>内容</p></callout>`（子块只允许 p / ol / ul / checkbox）

## 3. 定点编辑（文档已被他人手改过时必须用这条）

> 场景：同事已经在文档里手动改过报价数字。此时 **overwrite 会抹掉对方的手改**，必须定点改。

```bash
# ① 找章节标题的 block id
lark-cli --as bot docs +fetch --doc <token> --scope outline --detail with-ids --doc-format xml

# ② 列出该章节的顶层子块 id（注意翻页 page_token）
lark-cli --as bot api GET /open-apis/docx/v1/documents/<token>/blocks --params '{"page_size":500}'
#    用 parent_id == 文档 token 过滤顶层块，取「章节标题」到「下一章标题」之间的 id

# ③ 在章节标题后插入新内容（新内容里不要再写该章节标题）
lark-cli --as bot docs +update --doc <token> --doc-format markdown \
  --command block_insert_after --block-id <章节标题id> --content @./section.md

# ④ 批量删除旧内容块（逗号分隔）
lark-cli --as bot docs +update --doc <token> --command block_delete --block-id id1,id2,id3

# ⑤ 小范围改字
lark-cli --as bot docs +update --doc <token> --command str_replace \
  --pattern '旧文本' --content '新文本'
```

**顺序**：先插入、再删除 —— 这样任何一步失败都不会把章节删空。

## 4. 校验（每次写完必做）

```bash
lark-cli --as bot docs +fetch --doc <token> --doc-format markdown
```

- 检查标题是否唯一（旧标题残留 = 删漏了）
- 检查章节数、表格数、合计数字
- 检查重排后表格是否完整（fetch 会把表格导出成 `<table>` HTML，属正常）

## 5. 权限与身份

| 情况 | 表现 | 处理 |
|-|-|-|
| bot 可读可写 | fetch / update 均成功 | 正常使用 |
| bot 无共享管理权限 | `1063002` / `1063004`（permission-get-setting / member-list 失败） | 只能改正文，不能改分享设置或协作者 |
| user token 失效 | `need_user_authorization` | 用 `--as bot`；确需 user 身份时让用户重新授权 |

## 6. 坑位清单

- `@file` 只能相对路径；`--pattern` 不支持 `@file`
- 行内特殊字符（`*` `_` `[` `]` `$` `~` `<`）在 markdown 写入时需转义；行首 `#` `-` `+` `>` 位置敏感
- 表格 cell 内的 `|` 必须写成 `\|`
- 批量删除的 block id 必须在写入前**重新拉取**（结构变化后旧 id 可能失效）
- 写入完成后**版本号会前进**，即使是无副作用替换；不要在别人正在编辑时并发写
