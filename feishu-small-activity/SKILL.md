# Feishu Small Activity

## 触发边界

使用本 skill 处理：

- 产出或修改飞书文档中的半天/一天小型活动方案。
- 沙龙、圆桌、开放麦、Workshop、路演、分享会、闭门交流会、单场培训或单日活动。
- 用户要求“成熟、可交付、不要建议稿”的飞书活动文档。
- 已有飞书文档需要把主题、日期、嘉宾、流程、费用、分工改成确定版。

不要使用本 skill：

- 两天及以上、多会场、多模块复杂活动：使用 `大活动方案`。
- 只需要普通 Word/PDF 活动方案，不涉及飞书文档创建或更新：使用 `小活动方案`。
- 核心是合同、付款、验收、违约条款：使用 `活动合同`。

## 飞书操作规则

1. 先使用 `lark-doc` 和 `lark-shared`，并遵守 docs v2：`docs +fetch/+create/+update --api-version v2`。
2. 默认使用 XML / DocxXML，不主动切 Markdown；需要富 block、表格、callout、checkbox、whiteboard 时必须用 XML。
3. 飞书账号使用当前用户指定的稳定配置：优先 `--profile new-feishu`；身份按任务可行性选择，能用 bot 就 `--as bot`，bot 文档接口报 `99991672` 时报告真实阻塞，必要时用同 appId 的有效 user 授权完成文档交付。
4. 修改已有文档时，先 `docs +fetch` 读取当前内容；小改优先 `str_replace` 或 block 级更新，整篇语气和结构都要成熟化时可用 `overwrite`。
5. 完成后必须 fetch 验证关键字段，不只相信 update 返回成功。

## 文档结构

飞书小型活动交付文档默认使用以下结构：

1. 开头 callout：一句话锁定日期、形式、核心主题、活动价值。
2. 活动基础信息：名称、时间、形式、时长、规模、交付重点、费用。
3. 内容定位：三栏说明核心价值、内容路线、传播价值。
4. 首期主题：直接给定主题，不写“建议主题”；说明主题为何成立。
5. 圆桌追问方向：用 5-6 个具体问题支撑主题。
6. 嘉宾与圆桌设计：表格列出角色、嘉宾画像、承担内容。
7. 圆桌结构：用有序列表拆上下半场、茶歇、提问、切片沉淀；关键流程可加 mermaid 画板。
8. 执行流程：表格列出活动前、签到、开场、上半场、茶歇、下半场、收束、活动后。
9. 双方分工：两栏 grid，分别写我方/对方责任。
10. 共同确认事项：已确定项用 checked checkbox，未确定项保留 unchecked。
11. 交付物与费用：列明交付内容、金额、费用边界。
12. 活动价值沉淀：用 3 条以内总结内容资产、传播资产和后续复用价值。

## 写作口径

- 交付版不用“建议、可考虑、待确认主题、择期”等草案语气；日期、主题、费用等用户已确定的信息必须写成确定句。
- 小型活动不写宏大背景，重点写现场能怎么跑、谁负责、交付什么。
- 主题要聚焦一个清晰冲突或判断，不堆多个方向。
- 嘉宾画像服务于主题，不写泛泛“行业专家”。
- 流程表按 10-30 分钟粒度，半天活动一般控制在 2-3 小时主体时段。
- 费用边界要写清是否包含场地、茶歇、摄影摄像、物料、嘉宾差旅等第三方支出。

## 验证清单

- 文档链接可读取，更新后的 revision 变化。
- 日期、主题、费用、人数规模、交付物可用关键词 fetch 命中。
- 没有残留“建议主题、待确认日期、7 月第一周、择期”等与用户确定信息冲突的旧词。
- 每个 h1/h2 至少有一个非纯文本 block；连续纯文本不超过 3 段。
- 最终回复只给飞书链接和关键变更，不复述密钥或内部 token。
