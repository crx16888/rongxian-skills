# Five orange 合作 - 锦泰耐火材料 AI 生产流转助手文档范式

## 这个参考文件怎么用

当用户要求生成“好的文档”“像飞书里那样的文档”“给小白讲清楚”“从 0 到 1 讲明白传统业务线和新业务线”时，必须优先按本文件的层级和内容规范输出。

这不是完整 PRD 模板，不是技术设计文档，也不是咨询报告模板。它是一种面向团队、小白、客户沟通的业务说明文档。

核心特点：

```text
先讲传统工作流
再讲痛点
再用一个订单例子解释传统业务线
再用 10 个步骤讲新业务线
最后讲页面顺序、角色怎么用、MVP 怎么做
```

## 标准层级结构

生成文档时，优先使用以下标题层级。

```text
# 传统工作流

# 痛点

# 传统业务线可以用一个例子理解

# 新业务线 - 构建本体世界

### 第 1 步：录入客户订单

### 第 2 步：从订单生成工单 / 计划单

### 第 3 步：生成生产流转单

### 第 4 步：成型工序录入

### 第 5 步：烧结工序录入

### 第 6 步：检包工序录入

### 第 7 步：入库 / 出货记录

### 第 8 步：系统自动更新状态

### 第 9 步：老板 AI 查询

### 第 10 步：风险提醒

# MVP 应该怎么做
```

可以在“第 10 步：风险提醒”后补充两个小段，但不要提升成复杂 PRD：

```text
新业务线的核心页面顺序
新业务线里的每个人怎么用
```

## 内容规范

### 1. 传统工作流

这一节只做一件事：把现实工厂中一笔订单从客户到交付的自然流程讲清楚。

写法要像这样：

```text
客户说我要买一批货

-> 销售接单

-> 内勤/计划人员整理订单

-> 生产负责人安排生产

-> 车间开始生产

-> 工人按工序做产品

-> 质检/检包

-> 仓库入库

-> 出货给客户

-> 老板问进度时，人工去查
```

然后必须补一段“换成更具体的人和动作，就是：”

```text
客户
说：我要 1000 个某规格耐火材料，某天交货。

销售/内勤
记录客户、产品、数量、交期。

生产负责人
把订单变成生产任务，安排什么时候做、做多少。

车间成型人员
按要求把原料压制/成型。

烧结人员
把成型后的产品送进窑炉烧结。

检包人员
检查产品质量，统计合格、不良、报废、可修补。

仓库/发货人员
把合格品入库或发货。

老板
想知道订单做到哪一步、有没有延期、质量怎么样。
```

不要在这一节写系统架构、数据库、模块设计。

### 2. 痛点

这一节讲传统业务线的问题。重点不是说传统流程错了，而是说信息分散。

必须包含这个判断：

```text
传统业务线本身没有错。问题在于，很多中小制造企业的这些步骤不是在一个顺畅系统里完成的，而是分散的。
```

然后用短句列出：

```text
订单在老 ERP 里。
生产计划在 Excel 里。
生产流转单是纸质的。
工艺参数在老师傅经验里或纸上。
成型数据手写。
烧结数据手写。
检包数据手写。
出货可能又在另一个表里。
老板查询靠打电话问人。
```

再补一段“所以传统业务线可能是这样：”

```text
客户订单
在用友/ERP 里

生产计划
在 Excel 或微信群里

生产流转单
在纸上

成型记录
工人手写

烧结记录
工人手写

检包结果
质检手写或 Excel

出货信息
仓库系统/Excel/人工记录

老板查询
问销售、问生产、问仓库、翻纸质单据
```

不要把痛点扩展成十几条商业价值，不要写泛泛的数字化口号。

### 3. 传统业务线可以用一个例子理解

这一节必须用一个具体订单讲。

示例：

```text
假设客户 A 下了一个订单：

客户：江苏某钢厂
产品：耐火砖 A 型
规格：230x114x65
数量：10000 件
交期：6 月 30 日
```

然后用编号列出传统做法：

```text
1. 销售把订单录进 ERP，或者发给内勤。
2. 内勤通知生产负责人。
3. 生产负责人用 Excel 排计划。
4. 车间打印或手写一张生产流转单。
5. 成型工序做完后，在纸上写：今天成型 3000 件，废坯 50 件。
6. 烧结工序做完后，在纸上写：入窑 2950 件，出窑 2900 件，不良 80 件。
7. 检包工序写：合格 2800 件，可修补 50 件，报废 50 件。
8. 仓库人员再记录入库或出货。
9. 老板问“这个订单做到哪了”，需要有人去找纸、问车间、查 Excel。
```

最后一句收束：

```text
这就是传统业务线。
```

### 4. 新业务线 - 构建本体世界

这一节先给完整流程，不要一上来讲 AI。

标准写法：

```text
新业务线完整流程

1. 客户订单录入
2. 生成工单 / 计划单
3. 生成生产流转单
4. 成型工序录入
5. 烧结工序录入
6. 检包工序录入
7. 入库 / 出货记录
8. 系统自动汇总状态
9. 老板 AI 查询
10. 风险提醒
```

“构建本体世界”的意思可以简短解释为：

```text
把现实中的客户、订单、产品、工单、生产流转单、工序、质量结果、出货记录，变成系统里一个个清楚的对象和关系。
```

不要把这一节写成技术本体论，不要展开知识图谱，除非用户明确要求。

## 新业务线 10 步写作模板

每一步必须按这个顺序写：

```text
业务动作：

页面叫：

要填：

例子：

这一步的目的：
```

如果该步骤涉及系统自动变化，再加：

```text
提交后，系统自动：
```

### 第 1 步：录入客户订单

业务动作：

```text
客户下了一个订单。
系统里先建一条订单记录。
```

页面叫：

```text
订单列表 / 新建订单
```

要填：

```text
客户名称
订单号
产品名称
规格型号
订单数量
交付日期
销售负责人
备注
```

例子：

```text
客户：江苏某钢厂
订单号：DD20260613001
产品：耐火砖 A 型
规格：230x114x65
数量：10000 件
交期：2026-06-30
```

这一步的目的：

```text
系统知道客户要什么、要多少、什么时候交。
```

### 第 2 步：从订单生成工单 / 计划单

业务动作：

```text
生产负责人看订单，决定安排生产。
```

页面叫：

```text
生成生产计划
```

要填：

```text
计划生产数量
计划开始日期
计划完成日期
负责人
生产批次
备注
```

例子：

```text
订单要 10000 件。
生产负责人决定先生产 5000 件。
计划 6 月 15 日开始，6 月 22 日完成。
```

这一步的目的：

```text
把“客户要买什么”变成“工厂准备生产什么”。
```

必须补充：

```text
订单：客户要买。
工单：工厂要做。
```

### 第 3 步：生成生产流转单

业务动作：

```text
系统根据工单生成一张生产流转单。
这张单会跟着生产过程走。
```

页面叫：

```text
生产流转单详情
```

流转单里要有：

```text
流转单号
关联订单号
客户名称
产品名称
规格型号
计划数量
计划交期
当前工序
状态
```

例子：

```text
流转单号：LZ20260615001
订单号：DD20260613001
客户：江苏某钢厂
产品：耐火砖 A 型
计划数量：5000
当前工序：待成型
状态：未开始
```

这一步的目的：

```text
给车间一个明确的生产任务。
```

必须补一句：

```text
这张生产流转单就是新业务线的核心。
```

### 第 4 步：成型工序录入

业务动作：

```text
成型人员开始做产品。
做完后，在系统里录入成型结果。
```

页面叫：

```text
成型录入
```

要填：

```text
成型日期
班次
机台号
模具编号
料号
接收数量
完成数量
废坯数量
操作人
备注
```

例子：

```text
接收数量：5000
完成数量：4900
废坯数量：100
操作人：张三
```

提交后，系统自动：

```text
记录成型数据。
把流转单当前工序改成：待烧结。
```

这一步的目的：

```text
让系统知道这批货已经完成成型，下一步该烧结。
```

### 第 5 步：烧结工序录入

业务动作：

```text
烧结人员接收成型后的产品，进窑烧结。
烧结完成后，录入烧结数据。
```

页面叫：

```text
烧结录入
```

要填：

```text
窑炉编号
曲线号
装烧日期
进烧时间
出窑时间
装窑数量
出窑数量
不良数量
温度
保温时间
操作人
备注
```

例子：

```text
装窑数量：4900
出窑数量：4850
不良数量：80
窑炉编号：Y2
曲线号：QX-08
```

提交后，系统自动：

```text
记录烧结数据。
把流转单当前工序改成：待检包。
```

这一步的目的：

```text
让系统知道产品已经烧结完成，并记录烧结质量情况。
```

### 第 6 步：检包工序录入

业务动作：

```text
检包人员检查质量，统计合格、不良、报废、可修补。
```

页面叫：

```text
检包录入
```

要填：

```text
检包日期
接收数量
合格数量
可修补数量
轻微破损
局部黑点
小掉块
大掉块
有裂纹
损坏严重
黑料多
报废数量
操作人
备注
```

例子：

```text
接收数量：4850
合格数量：4700
可修补数量：80
报废数量：70
```

系统自动计算：

```text
不良数量
不良率
报废率
```

提交后，系统自动：

```text
把流转单状态改成：检包完成 / 待入库 / 待出货。
```

这一步的目的：

```text
让系统知道最终有多少合格品、多少不良、多少报废。
```

### 第 7 步：入库 / 出货记录

业务动作：

```text
合格品进入仓库，或者直接出货给客户。
```

页面叫：

```text
入库/出货记录
```

要填：

```text
入库数量
出货数量
出货日期
物流信息
收货客户
经办人
备注
```

例子：

```text
合格 4700 件。
先入库 4700 件。
其中 3000 件 6 月 25 日出货。
```

提交后，系统状态变成：

```text
已入库
部分出货
已出货
已完成
```

这一步的目的：

```text
让生产结果和客户交付衔接起来。
```

### 第 8 步：系统自动更新状态

这一节要强调：不需要人额外做，是系统自动判断。

标准内容：

```text
成型提交后 -> 当前工序变成待烧结
烧结提交后 -> 当前工序变成待检包
检包提交后 -> 当前工序变成待入库/待出货
出货完成后 -> 状态变成已完成
超过交期还没完成 -> 状态变成延期
某个工序超过 3 天没更新 -> 状态变成停滞风险
不良率超过阈值 -> 标记质量异常
```

这一步的目的：

```text
不用老板问人，系统自己知道每张单现在在哪里。
```

### 第 9 步：老板 AI 查询

先讲老板怎么问：

```text
江苏某钢厂的订单做到哪了？
哪些生产单延期了？
今天有哪些单子要完成？
哪个产品不良率最高？
哪些已经检包但还没出货？
```

必须强调：

```text
AI 不应该乱回答。它应该查系统里的数据后回答。
```

示例回答：

```text
问题：江苏某钢厂的订单做到哪了？

回答：
江苏某钢厂订单 DD20260613001 当前已完成烧结，待检包。
计划数量 5000 件，成型完成 4900 件，烧结出窑 4850 件。
计划交期为 2026-06-30，目前暂无延期风险。
数据来源：生产流转单 LZ20260615001、烧结记录 2026-06-18。
```

最后强调：

```text
AI 回答必须有来源。
不能凭空编。
```

### 第 10 步：风险提醒

标准内容：

```text
系统每天自动检查：

哪些单快延期？
哪些单已经延期？
哪些工序太久没更新？
哪些产品不良率太高？
哪些检包完成但还没出货？
哪些数据缺失？
```

风险示例：

```text
风险类型：延期风险
流转单号：LZ20260615001
客户：江苏某钢厂
产品：耐火砖 A 型
原因：计划交期还有 2 天，但当前仍在烧结阶段
建议：生产负责人确认检包和出货安排
```


## 可选补充段：新业务线里的每个人怎么用

标准内容：

```text
销售 / 内勤：
录入客户和订单。
上传客户订单 Excel 或合同。

生产负责人：
从订单生成工单/计划单。
创建生产流转单。
查看所有生产进度。
处理延期和异常。

成型人员：
只进入成型录入页。
填完成数量、废坯数量、机台、模具、操作人。

烧结人员：
只进入烧结录入页。
填窑炉、曲线号、装窑数量、出窑数量、不良数量。

检包人员：
只进入检包录入页。
填合格数量、不良分类、报废数量、可修补数量。

仓库 / 出货人员：
填入库数量、出货数量、出货日期。

老板：
看首页。
问 AI。
看风险日报。
```

## MVP 应该怎么做

这一节必须收敛，不要展开成长期路线图。

标准写法：

```text
第一版不要做太复杂。就做一条样例流程。

使用虚拟数据生成平台生成一个假订单跑通：

客户：江苏某钢厂
产品：耐火砖 A 型
数量：5000
交期：2026-06-30
```

然后列 10 步：

```text
1. 新建客户
2. 新建产品
3. 新建订单
4. 生成生产流转单
5. 填成型记录
6. 填烧结记录
7. 填检包记录
8. 填入库/出货记录
9. 老板查询订单进度
10. 系统显示风险日报
```

结尾可以写：

```text
然后针对 MVP 去生成视频和效果报告，和厂家谈判。
```

## 禁止偏离

生成这类文档时，不要默认加入以下内容，除非用户明确要求：

```text
数据库表设计
接口清单
复杂权限体系
完整 ERP 边界论证
6 周项目计划
技术架构
模型选型
成本估算
大段商业价值
咨询报告式背景分析
```

如果需要补充这些内容，必须放在正文之后，并标为“后续可扩展内容”，不能破坏飞书示例文档的主结构。
