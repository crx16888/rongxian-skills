# 活动方案路由

## 触发边界

只在活动方案规模不明确时使用本 skill 做分流。

- 半天或一天周期，流程相对简单：转用 `小活动方案`。
- 两天及以上，或多模块、多场地、多组织方、多阶段筹备：转用 `大活动方案`。
- 用户明确说沙龙、分享会、单日 Workshop、单日路演、小型校园活动：转用 `小活动方案`。
- 用户明确说峰会、展会、科技节、黑客松、赛事、训练营、活动周：通常转用 `大活动方案`，除非用户明确只有半天/一天。

不要使用本 skill：

- 用户核心在写 AI 课程、培训体系、课程表、教学大纲、讲师安排：转用 `AI课程培训`。
- 用户核心在写合同、服务协议、报价条款、付款违约、知识产权、保密、验收条款：转用 `活动合同`。
- 用户只是要画流程图、甘特图、组织图并落地飞书画板：使用 `design-lark-chart`。

## 工作流

1. 先从用户输入或现有文件里确认活动周期：半天、一天、两天、多天、长期系列。
2. 再确认复杂度：是否多模块、多会场、多组织方、住宿交通、招商赞助、安保医疗、赛事评审。
3. 能明确判断就直接切换到 `小活动方案` 或 `大活动方案`，不要继续用本 skill 写正文。
4. 如果周期和复杂度都不明确，先按缺失事实问一个短问题；若用户要求先做，则默认半天/一天为小活动，两天及以上为大活动。

## 输出结构

本 skill 不直接产出完整方案正文，只负责路由。

## 写作口径

- 路由判断优先看稳定事实：活动天数、活动类型、场地数量、参与方数量、是否住宿交通、是否招商赞助。
- 不要因为文件名叫“活动方案”就默认使用某一个子 skill；先看内容边界。
